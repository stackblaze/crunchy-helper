# pg-db-manager

Manage databases on a **Crunchy PGO** cluster: list, create, delete, restore from pgBackRest, and manage users.

**[github.com/stackblaze/pg-db-manager](https://github.com/stackblaze/pg-db-manager)**

## Prerequisites

Python 3.7+, **kubectl** in PATH (pointing at the cluster that runs PGO).

## Quick start

```bash
git clone https://github.com/stackblaze/pg-db-manager.git && cd pg-db-manager
pip install -r requirements.txt
./manager.py list          # setup runs automatically if not configured
./manager.py create        # create DB + user
./manager.py restore       # restore from backup
./manager.py users list    # list users
```

Setup explicitly: `python -m pg_db_manager.setup`

## Portable use

Copy the project to another host (`scp -r pg-db-manager user@host:` or `tar -czf pg-db-manager.tar.gz pg-db-manager`). On the new machine, extract, run `pip install -r requirements.txt`, then run `./manager.py` — setup will prompt for that cluster’s kubeconfig/API. Use separate copies or `PG_DB_MANAGER_ENV` for multiple clusters.

## Config

- **pg-db-manager.env** — Generated by setup; holds KUBECONFIG, PG_HOST, NAMESPACE, CLUSTER. Editable; `${SCRIPT_DIR}` works when the folder is copied.
- **PG_DB_MANAGER_ENV** — Optional; point to another env file.

## Commands

- `./manager.py list [--db NAME]` — List DBs; optional connection info for one
- `./manager.py create [--db NAME] [--user USER] [--password PASS]` — Create DB and user
- `./manager.py delete [--db NAME] [--yes]` — Delete a database
- `./manager.py restore [--backup LABEL] [--source-db NAME] [--as NAME] [--yes]` — Restore from pgBackRest
- `./manager.py users list | create | delete | reset-password` — Manage users

## Restore flow

PVC per (database, backup date) → restore pod (pgbackrest from S3 to PVC) → extract pod (pg_dump to PVC) → copy dump to primary and pg_restore. The `pgbouncer` schema is excluded.
